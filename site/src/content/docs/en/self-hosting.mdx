Casthop has two parts:

- **Media servers:** LiveKit (moves audio and video between browsers), Egress (mixes, records and streams out), Redis (lets them talk) and an RTMP server. These run in Docker on a machine you control.
- **App server:** a Cloudflare Worker with Durable Objects (one per studio) and D1 (a small database). It serves the studio UI and the API.

Get the [local quick start](/docs/getting-started) working first. Self-hosting is the same setup with real keys and public addresses.

## 1. Run the media servers

Start from [`docker-compose.yml`](https://github.com/casthop/casthop/blob/main/docker-compose.yml) and the config files in [`infra/`](https://github.com/casthop/casthop/tree/main/infra). Locally they bind `127.0.0.1`. On a server, LiveKit must be reachable by your guests, usually as `wss://` behind TLS. The RTMP server can be MediaMTX, nginx-rtmp, or nothing at all if you only stream to YouTube and other real sites.

## 2. Make real API keys

The repo ships public test keys (`devkey`). Make your own:

```bash
lk generate-keys
```

Put the key and secret in `infra/livekit.yaml` (`keys:` and `webhook.api_key`) and `infra/egress.yaml`. The app returns 503 if the test keys are used with a LiveKit that is not on `127.0.0.1`. This is on purpose.

## 3. Create the Cloudflare resources

```bash
bunx wrangler d1 create casthop
bunx wrangler r2 bucket create casthop-recordings
```

Copy the D1 `database_id` it prints into `wrangler.jsonc`. The tables are created on the first request, so there is no migration step.

## 4. Set the variables and secrets

In `wrangler.jsonc` under `vars`, set at least `LIVEKIT_API_KEY`, `LIVEKIT_HTTP_URL`, `PUBLIC_LIVEKIT_URL`, `EGRESS_TEMPLATE_URL` and `PUBLIC_ORIGIN`. Then add the secrets:

```bash
bunx wrangler secret put LIVEKIT_API_SECRET
bunx wrangler secret put HOST_KEY_SECRET
```

Use a separate random value for `HOST_KEY_SECRET`. Without it, host keys use the LiveKit secret, so changing LiveKit keys later would lock you out of existing studios.

Set `MAIL_WEBHOOK_URL` so sign-in emails go to a real mailer. Every setting is in [Configuration](/docs/configuration).

## 5. Build and deploy

```bash
bun install
bun run build
bunx wrangler deploy
```

Open `https://<your site>/api/health`. You should see `"ok":true`.

## 6. Point LiveKit at the app

Set LiveKit `webhook.urls` to:

```
https://<your site>/api/livekit/webhook
```

The webhooks are signed with your LiveKit key. This is how the studio learns that Egress crashed or a stream dropped, so it can retry. Egress must also be able to open `EGRESS_TEMPLATE_URL`.

## 7. Proxies

If the app sits behind your own reverse proxy, set `CASTHOP_TRUST_FORWARDED=1` so sign-in and guest limits see the real client address. On Cloudflare you do not need it.

## Destinations, replays and clips

- Studio owners enter real YouTube, LinkedIn, X or other RTMP addresses per studio. See [Destinations](/docs/destinations).
- The mixed MP4 goes to the Egress output folder. Turn it into a replay with `casthop-post hls`, then `POST /api/studios/:id/replays` with `visibility` set to `private` or `public`. Private replays are for the owner and co-hosts. Public ones play at `/watch/:id`.
- While live, **Clip** (or the C key) saves the last 30 or 60 seconds. Clips follow the same private and public rules.

## Limits built in

- Sign-in: every 15 minutes, 5 link requests per network and 3 links per email.
- Guests: each network (one IPv4 address or one IPv6 /64) can add up to 10 new guests a minute and hold 16 guest slots in a studio. Guests who left more than a minute ago free their slot when the studio is full.

## Not included yet

- **TURN.** Guests behind strict firewalls may not connect. Run your own TURN server with LiveKit if you need it.
- **X and LinkedIn chat.** YouTube, Twitch and Kick chat work. X has no free chat API, and LinkedIn needs a partner API.

Measure your own setup before you rely on it. Recorded numbers are in [`MEASUREMENTS.md`](https://github.com/casthop/casthop/blob/main/MEASUREMENTS.md).
