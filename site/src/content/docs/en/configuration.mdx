Casthop reads its settings from two files:

- **`.env`** is for Docker Compose (the media servers). Start from `.env.example`.
- **`.dev.vars`** is for the app server (the Cloudflare Worker) when you run `bun run dev`. Start from `.dev.vars.example`.

On a real server, set the app values as Worker variables, and the secret ones with `wrangler secret put NAME`. Never commit real values to git.

For a local test, you do not need to change anything. The defaults work.

<p class="note">The <code>devkey</code> and <code>casthop_dev_secret_…</code> values in the example files are public test keys. Casthop refuses them unless LiveKit is on <code>127.0.0.1</code>. Make your own with <code>lk generate-keys</code> before you put anything on a network.</p>

## LiveKit

LiveKit is the server that carries audio and video between browsers.

| Name | What it does | When to change it | Default |
|---|---|---|---|
| `LIVEKIT_API_KEY` | Key the app uses to talk to LiveKit. | On any real server. Use your own key. | `devkey` |
| `LIVEKIT_API_SECRET` | Secret that goes with the key. Never sent to browsers. | On any real server. Store it as a Worker secret. | public test value |
| `LIVEKIT_HTTP_URL` | Where the app server reaches LiveKit. | When LiveKit runs on another host. | `http://127.0.0.1:7880` |
| `PUBLIC_LIVEKIT_URL` | Where browsers reach LiveKit. Must be reachable by your guests. | On any real server, for example `wss://livekit.example.com`. | `ws://127.0.0.1:7880` |

## Recording and mixing

Egress is the LiveKit service that opens a hidden studio page, mixes the stage into one video, records it, and sends it out.

| Name | What it does | When to change it | Default |
|---|---|---|---|
| `EGRESS_TEMPLATE_URL` | The studio page Egress opens to mix the video. | On a real server: `https://<your site>/egress-template`. | `http://127.0.0.1:5173/egress-template` |
| `EGRESS_OUTPUT_DIR` | Folder inside the Egress container where recordings go. Docker only, not read by the app. | Rarely. Compose mounts `./data/recordings` here. | `/out` |

## Default destinations

A destination is a streaming address (RTMP URL) such as YouTube's ingest.

| Name | What it does | When to change it | Default |
|---|---|---|---|
| `RTMP_YOUTUBE` | Default YouTube address for new studios. | Only to point at another local test server. | `rtmp://127.0.0.1:1935/live/youtube` |
| `RTMP_LINKEDIN` | Default LinkedIn address. | Same as above. | `rtmp://127.0.0.1:1935/live/linkedin` |
| `RTMP_X` | Default X address. | Same as above. | `rtmp://127.0.0.1:1935/live/x` |

New studios copy these only when they point at `127.0.0.1`. Do not put a real stream key here. Any account can create a studio, so the key would reach everyone. Owners enter their real addresses per studio in the **Destinations** panel.

## Server and security

| Name | What it does | When to change it | Default |
|---|---|---|---|
| `PUBLIC_ORIGIN` | Your public site address, used in sign-in emails, co-host invites and the GitHub callback. | Always on a real server, for example `https://studio.example.com`. Without it, sign-in fails off `127.0.0.1`. | unset |
| `HOST_KEY_SECRET` | Separate secret for host keys inside the app. Falls back to `LIVEKIT_API_SECRET`. | Always on a real server, so changing LiveKit keys later does not lock out studios. | unset |
| `CASTHOP_TRUST_FORWARDED` | `1` trusts the client address from `X-Forwarded-For` and `CF-Connecting-IP`. Sign-in and guest limits use that address. | Only behind your own reverse proxy (nginx, Caddy). Not needed on Cloudflare. Never for `bun run dev`. | unset |
| `CASTHOP_DEV` | `1` is local development: sign-in links are printed in the terminal instead of mailed. Refused unless LiveKit and `PUBLIC_ORIGIN` are on `127.0.0.1`. | Set in `.dev.vars.example`. Never on a deployed Worker. | `1` locally |
| `CASTHOP_DEV_LOGIN` | `1` returns the sign-in link in the browser response, not only in the terminal. Works only on `127.0.0.1`. | For e2e tests, `bun run measure` and `/internal/probe`. Never on a server. | unset |
| `CASTHOP_ALLOW_DEV_KEYS` | `1` allows the public test keys with a LiveKit that is not on `127.0.0.1`. | Tests only. | unset |

`X_LOCAL_EXPLORER=true` in your shell (not `.dev.vars`) turns on the local data browser in `bun run dev`. It is off by default.

## Sign-in

Hosts sign in with an email link. Guests never need to.

| Name | What it does | When to change it | Default |
|---|---|---|---|
| `MAIL_WEBHOOK_URL` | Casthop POSTs JSON `{ to, subject, text }` here for each email. | On a real server, pointed at your mail service. Unset prints emails to the terminal. | unset |
| `MAIL_WEBHOOK_TOKEN` | Sent as `Authorization: Bearer <token>` with each webhook call, so your mailer can check it. | If your mail webhook needs auth. | unset |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | Turns on "Sign in with GitHub". Make an OAuth app on GitHub with the callback `<PUBLIC_ORIGIN>/api/auth/github/callback`. | If you want GitHub sign-in. Unset hides the button. | unset |

## Chat from streaming sites

While you are live, comments from these sites show up in the studio chat. Hosts and co-hosts can pin one onto the video. Unset means the feature stays hidden. Nothing breaks.

| Name | What it does | Default |
|---|---|---|
| `YOUTUBE_API_KEY` | YouTube Data API key to read public live chat. | unset |
| `YOUTUBE_LIVE_CHAT_ID` | Read this live chat directly. Use with the API key. | unset |
| `YOUTUBE_VIDEO_ID` | Find the live chat from this video. Use with the API key. | unset |
| `YOUTUBE_OAUTH_CLIENT_ID`, `YOUTUBE_OAUTH_CLIENT_SECRET`, `YOUTUBE_OAUTH_REFRESH_TOKEN` | Instead of an id, find your own active broadcast. | unset |
| `YOUTUBE_CHAT_STUDIO_ID` | The studio id (or comma-separated ids) that shows this YouTube chat. Unset, no studio polls it. | unset |
| `TWITCH_CHANNEL` | Twitch channel name to read. No login needed. | unset |
| `KICK_CHATROOM_ID` | Kick chatroom number to read. | unset |

For YouTube, set either the API key plus one id, or the three OAuth values. X chat is not supported because X has no free chat API. LinkedIn comments are not supported.

## Timing

You should not need these. Tests set some of them to `0`.

| Name | What it does | Default |
|---|---|---|
| `CASTHOP_EMPTY_GRACE_MS` | End the stream after the studio has been empty this long. | `45000` (45 s) |
| `CASTHOP_COMPOSITOR_GRACE_MS` | How long to wait for the mixing page to join after starting. | `15000` |
| `CASTHOP_RECOVERY_MS` | Stop retrying a crashed mixer after this. The host can press Retry. | `30000` |
| `CASTHOP_MAX_STUDIOS` | How many studios one account can own. | `20` |
| `CASTHOP_HEARTBEAT_MS` | Treat the mixing page as dead after this much silence. It checks in every second. | `3000` |
| `CASTHOP_BACKOFF_MS` | Wait between stream retries. Unset means 1, 2, 4, 8, 16, then 30 s. | unset |

## Cloudflare bindings

These are set in `wrangler.jsonc`, not as variables.

| Binding | What it is |
|---|---|
| `DB` | D1 database for accounts, sessions and the studio list. Tables are created on first request. |
| `STUDIO` | One Durable Object per studio: stage, layout, chat and destinations. |
| `RECORDINGS` | R2 bucket for replays, clips and per-person tracks. |

## Stream keys

Stream keys are not settings. They are saved per studio in Durable Object storage. Guests and public pages only see the last few characters, plus a `hasKey` flag.

## Hosted mode (optional)

A hosted version of Casthop is coming. These hooks let a separate service run Casthop for many teams. You do not need them to self-host. Each one is off unless its variable is set, and with none set nothing changes.

A tenant id is the id of one customer team in that service. Studios created through the service API carry it, and their files are stored under `t/<tenantId>/`.

| Name | What it does |
|---|---|
| `CASTHOP_EXTERNAL_AUTH_KEYS` | Comma list of `kid:secret` (secret 32+ characters). Turns on `GET /api/auth/external`. Otherwise it returns 404. |
| `CASTHOP_EXTERNAL_AUTH_ISSUER` | Required with the keys. The token `iss` must equal it. |
| `CASTHOP_SIGNIN` | `external` turns off email and GitHub sign-in, and creating studios from the app (both 403 `signin_external`). Studios then come from the service API, so each one has a tenant. Existing sessions and guest links keep working. `/api/config` returns `signin: "external"`. |
| `CASTHOP_SERVICE_KEYS` | Comma list of `kid:secret` (secret 32+ characters). Turns on the signed `/api/service/*` API. Otherwise those routes return 404. |

### Sign-in handoff

`GET /api/auth/external?token=<jwt>&next=<path>` signs the user in and redirects to `next`. `next` must start with a single `/` (no `//`, no backslash). Anything else goes to `/`.

The token is a compact JWS, HS256, with header `{"alg":"HS256","typ":"JWT","kid":"<kid>"}`.

| Claim | Rule |
|---|---|
| `iss` | Equals `CASTHOP_EXTERNAL_AUTH_ISSUER`. |
| `aud` | `casthop`. |
| `sub` | External user id, a string. |
| `email` | Valid email. The account is found or created by it, and pending invites are applied. |
| `exp` | Unix seconds, in the future and at most 120 s from now. |
| `iat` | Unix seconds. |
| `jti` | String, 128 characters or fewer. One use only. |
| `name` | Optional. |
| `tenant` | Optional. If present it must be a valid tenant id. |

### Service API

Every request to `/api/service/*` carries these headers:

| Header | Value |
|---|---|
| `X-Casthop-Key-Id` | The `kid`. |
| `X-Casthop-Timestamp` | Unix seconds. Must be within 300 s of the Worker clock. |
| `X-Casthop-Nonce` | 16 to 64 characters of `A-Za-z0-9_-`. Used once. |
| `X-Casthop-Signature` | Lowercase hex HMAC-SHA256. |

The signature is the HMAC-SHA256 of this string, keyed with the secret:

```text
${timestamp}\n${nonce}\n${METHOD}\n${pathname+search}\n${sha256hex(body)}
```

`body` is the raw request body, or the empty string when there is none. A bad signature, stale timestamp, unknown key or reused nonce returns 401 `{"error":"bad_signature"}`.

| Route | Does |
|---|---|
| `POST /api/service/studios` | Body `{tenantId, ownerEmail, ownerName?, name?}`. Creates a studio for the tenant. Returns 201 `{studio:{id,name,tenantId,ownerId}}`. |
| `GET /api/service/tenants/:tenantId/studios` | Returns `{studios:[{id,name,ownerId,createdAt}]}`. |
| `DELETE /api/service/studios/:id?tenantId=…` | Ends live output, deletes the studio's state, rows and files. 404 if it is not in that tenant. Returns `{deleted:true}`. |
| `DELETE /api/service/tenants/:tenantId` | Does the same for every studio of the tenant, then removes everything under `t/<tenantId>/`. Returns `{deleted:n}`. |

Accounts are never deleted by these routes.

A tenant id matches `^[a-z0-9][a-z0-9_-]{0,62}$`. Files of a studio with a tenant id are stored under `t/<tenantId>/` in the recordings bucket. Studios without one keep their keys.
