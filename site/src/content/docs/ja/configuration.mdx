docker compose 用に `.env.example` を `.env` へ、Worker 用に `.dev.vars.example` を `.dev.vars` へコピーします。本番では Worker の値を Worker secrets か vars として置きます。両方の example に、アプリが読む変数が一行コメント付きで並んでいます。

<p class="note">example ファイルの <code>casthop_dev_secret_…</code> は、文書化されたローカル既定値です。公開されているので本番には使いません。キーは <code>lk generate-keys</code> で自分で作ってください。</p>

## LiveKit

| 名前 | 用途 | ローカルの既定値 |
|---|---|---|
| `LIVEKIT_API_KEY` | LiveKit の API キー。 | `devkey` |
| `LIVEKIT_API_SECRET` | LiveKit の API シークレット。Worker secrets に置き、ブラウザへ送らないでください。 | 文書化されたローカル既定値。本番には使わない |
| `LIVEKIT_HTTP_URL` | Worker が LiveKit に届く先。 | `http://127.0.0.1:7880` |
| `PUBLIC_LIVEKIT_URL` | ブラウザがつなぐ LiveKit の URL。 | `ws://127.0.0.1:7880` |

`devkey` をループバック以外の LiveKit URL と組み合わせると、Worker は 503 を返します。`CASTHOP_ALLOW_DEV_KEYS=1` はこれを上書きし、テスト専用です。

## Egress

| 名前 | 用途 | ローカルの既定値 |
|---|---|---|
| `EGRESS_OUTPUT_DIR` | egress コンテナ内のパス。Compose はここに `./data/recordings` をマウントします。Worker の変数ではありません。 | `/out` |
| `EGRESS_TEMPLATE_URL` | Egress が開くコンポジターページ。 | `http://127.0.0.1:5173/egress-template` |

## 配信先

| 名前 | 用途 | ローカルの既定値 |
|---|---|---|
| `RTMP_YOUTUBE` | YouTube の既定配信先。 | `rtmp://127.0.0.1:1935/live/youtube` |
| `RTMP_LINKEDIN` | LinkedIn の既定配信先。 | `rtmp://127.0.0.1:1935/live/linkedin` |
| `RTMP_X` | X の既定配信先。 | `rtmp://127.0.0.1:1935/live/x` |

ローカルの MediaMTX 代替です。本番のインジェスト URL が用意できたら差し替え、本物のストリームキーはコミットしないでください。

## Worker

| 名前 | 用途 | ローカルの既定値 |
|---|---|---|
| `HOST_KEY_SECRET` | Worker から Durable Object へのホストキー用の別 HMAC。未設定だと `LIVEKIT_API_SECRET` に落ちます。本番では設定してください。 | unset |
| `PUBLIC_ORIGIN` | マジックリンクのメール、共同ホスト招待、GitHub OAuth に使う公開サイト URL。 | unset（ループバックの Host を使う） |
| `CASTHOP_TRUST_FORWARDED` | リバースプロキシの後ろで `CF-Connecting-IP` と `X-Forwarded-For` を信じるときは `1`。 | unset |
| `CASTHOP_ALLOW_DEV_KEYS` | 公開 dev キーペアを、ループバック以外の LiveKit と一緒に許可する。テスト専用。 | unset |

## タイミングの上書き

任意です。未設定なら `worker/egress.ts` のコード既定値が使われます。テストでは一部を `0` や数ミリ秒にします。

| 名前 | 用途 | 既定値 |
|---|---|---|
| `CASTHOP_EMPTY_GRACE_MS` | スタジオがこの時間空いたらライブを終える。 | `45000` |
| `CASTHOP_COMPOSITOR_GRACE_MS` | StartRoomComposite のあと、コンポジターの Chrome が参加するまで待つ。 | `15000` |
| `CASTHOP_RECOVERY_MS` | 死んだコンポジターの再起動を諦める。ホストは再試行できる。 | `30000` |
| `CASTHOP_HEARTBEAT_MS` | この時間を過ぎるとコンポジターの beat は古い（ページは 1 秒ごとに POST）。 | `3000` |
| `CASTHOP_BACKOFF_MS` | RTMP 再試行のバックオフを上書き。Unset = 1 s、2 s、4 s、8 s、16 s、30 s。テストでは `0`。 | unset |

## サインイン

| 名前 | 用途 | ローカルの既定値 |
|---|---|---|
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | 任意の GitHub OAuth。未設定だと GitHub ボタンは出ない。 | unset |
| `MAIL_WEBHOOK_URL` | 任意。Casthop は JSON `{ to, subject, text }` を POST する。未設定だとマジックリンクは Worker コンソールへ。 | unset |
| `MAIL_WEBHOOK_TOKEN` | メール webhook 用の任意トークン。 | unset |

## YouTube ライブチャット

番組がライブ中、YouTube 配信のコメントがスタジオのチャットパネルに出ます。ホストは 1 件をコンポジターのオーバーレイにピンできます。資格情報が無いと隠れ、スタジオはエラーになりません。

| 名前 | 用途 | ローカルの既定値 |
|---|---|---|
| `YOUTUBE_API_KEY` | 公開 `liveChatMessages.list` 用の YouTube Data API キー。 | unset |
| `YOUTUBE_LIVE_CHAT_ID` | 検索を飛ばして、このライブチャットをポーリングする。 | unset |
| `YOUTUBE_VIDEO_ID` | 動画から `activeLiveChatId` を解決する。 | unset |
| `YOUTUBE_OAUTH_CLIENT_ID`, `YOUTUBE_OAUTH_CLIENT_SECRET`, `YOUTUBE_OAUTH_REFRESH_TOKEN` | オーナーの進行中配信を探す（`liveBroadcasts.list?mine=true`）。 | unset |

API キーにライブチャットか動画 ID を足すか、OAuth リフレッシュの 3 点が必要です。ポーリングは API の `pollingIntervalMillis` に従います。X の API は有料プラン、LinkedIn のコメントはパートナー API が要り、それらの配信先は取り込みません。

## Twitch と Kick のチャット

配信中、これらのコメントは同じチャットパネルに表示されます。未設定なら表示されません。

| 名前 | 用途 | ローカルの既定値 |
|---|---|---|
| `TWITCH_CHANNEL` | 読み取る Twitch チャンネル名。 | unset |
| `KICK_CHATROOM_ID` | 読み取る Kick のチャットルーム ID（数字）。 | unset |

X のチャットは、無料のチャット API がないため、まだ対応していません。

## ストリームキー

ストリームキーは環境変数ではありません。Durable Object のストレージにあり、リポジトリには入りません。公開 API が返すのは `rtmp://…/xxxx` のようなマスクした末尾と、`hasKey` フラグだけです。
