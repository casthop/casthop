## ブラウザ

UI は TypeScript です。メディアの重い処理は、`crates/casthop-media` の Rust を WebAssembly にコンパイルしたもので、JS のインポートがないため AudioWorklet の中でも安全に動きます。

- **音声:** RNNoise によるノイズ抑制と VAD/メーターが、マイクを LiveKit に公開する前に AudioWorklet で動きます。`?fx=js` や `?fx=off` で比較できます。
- **レイアウトと合成:** レイアウトは WASM が計算します。ライブの合成は、WebCodecs が使えるとき、専用 Worker 上の Canvas2D と OffscreenCanvas で行います（`?thread=main` で従来のメインスレッドの経路に戻せます）。`?compose=wasm` は CPU ブリット、`?compose=webgpu` は Rust の GPU 経路、`?compose=webgpu-ts` は TypeScript の GPU 経路です。既定は Canvas2D のままです。ベンチでは GPU が勝てませんでした。
- **カメラのぼかし:** MediaPipe Selfie Segmenter を使います。`@mediapipe/tasks-vision` とそのモデルは、ぼかしをオンにしたときだけ、このオリジンから読み込まれます。CDN は使いません。

CI のジョブ `perf` が、Chrome で合成の main と worker を比較します（`PERF=1 bun run test:perf`）。数値は [`MEASUREMENTS.md`](https://github.com/casthop/casthop/blob/main/MEASUREMENTS.md) にあります。

## LiveKit を SFU として使い続ける

LiveKit（Go）はすでに十分速いので、Casthop は置き換えません。ブラウザは WebRTC のサイマルキャストで公開し、Egress はフル品質で購読します。

## Egress のファンアウトを選ぶ理由

Cloudflare Stream Live には、Stream を有効にした Cloudflare アカウントが必要で、Stream のストレージは前払いです。このプロトタイプは、有料サービスには登録しません。Egress は、すでに 1 回だけトランスコードし、その 1 回のエンコードから多数の RTMP URL へ出力できます。これがセルフホストの方法です。ホスト型の Casthop では、配信にかかる費用の計算が合えば、将来 1 本の RTMP を Stream に入れる可能性もあります。リポジトリの [`MEASUREMENTS.md`](https://github.com/casthop/casthop/blob/main/MEASUREMENTS.md) を見てください。

## コントロールプレーン

アプリは Hono の Worker で、スタジオごとに 1 つの Durable Object（ステージ、レイアウト、チャット、配信先）を持ち、スタジオの一覧には D1 を使います。R2 には、HLS のリプレイ、ライブのクリップ、ショーの間に各ブラウザからアップロードされる個人別の ISO チャンクを保存します。Egress は、元の MP4 を引き続き録画用ボリュームに書き込みます。`casthop-post hls` がそれをパッケージし、Worker が配信します。負荷の高い Worker のエンドポイントは TypeScript のままです。workers-rs への移植も計測しましたが（`bun run bench:worker`）、CPU、コールドスタート、バンドルサイズのどれでも勝てませんでした。

## 配信先のチャット

ライブ中は、設定があれば、スタジオの Durable Object が YouTube（`liveChatMessages.list`）、Twitch、Kick のチャットを読み取ります（`worker/chat-ingest.ts`、`worker/chat-platforms.ts`）。コメントは、ルーム内のチャット一覧に加わります。ホストと共同ホストは、コメントを 1 件、Canvas2D のオーバーレイにピン留めできます。YouTube のポーリング用カーソルは、公開されるスタジオの状態には含まれません。X と LinkedIn は読み取りません。

## Live バッジ

スタジオのステータス表示が `live` になるのは、Egress が実際に出力しているときだけです。つまり、ストリームのバイト数か再生時間が出ているとき、または RTMP の `started_at` の少しあとです（LiveKit は、MediaMTX にストリームが届く前に開始を報告することがあります）。それまでは Starting のままです。コンポジターの Chrome が落ちると、ハートビートが途切れて Live が外れ、スタジオはバックオフしながら再試行します。

## casthop-post

`crates/casthop-post` は、R2 のリプレイビューアー向けに、検査、リミックス、HLS のパッケージ化を行います。`clip` は、パッケージ済みのディレクトリから、直前の N 秒をコピーします。[配信先](/docs/destinations) を見てください。
