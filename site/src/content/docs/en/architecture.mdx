## Browser

The UI is TypeScript. Media hot paths are Rust compiled to WebAssembly in `crates/casthop-media`, with no JS imports so it is safe in an AudioWorklet.

- **Audio:** RNNoise noise suppression and VAD/meters run in an AudioWorklet before the mic is published to LiveKit. `?fx=js` or `?fx=off` lets you compare.
- **Layout and compositing:** WASM computes the layout. The live compositor is Canvas2D on a dedicated Worker with OffscreenCanvas when WebCodecs is present (`?thread=main` forces the old main-thread path). `?compose=wasm` is the CPU blit, `?compose=webgpu` the Rust GPU path, `?compose=webgpu-ts` the TypeScript GPU path. Canvas2D stays default; GPU did not win on the bench.
- **Camera blur:** uses MediaPipe Selfie Segmenter. `@mediapipe/tasks-vision` and its model load only when blur is on, from this origin, with no CDN.

CI job `perf` compares compositor main vs worker in Chrome (`PERF=1 bun run test:perf`). Numbers: [`MEASUREMENTS.md`](https://github.com/casthop/casthop/blob/main/MEASUREMENTS.md).

## LiveKit stays the SFU

LiveKit (Go) is already the fast path, so Casthop does not replace it. Browsers publish with WebRTC simulcast, and Egress subscribes at full quality.

## Why Egress fan-out

Cloudflare Stream Live needs a Cloudflare account with Stream enabled, and Stream storage is prepaid. This prototype does not sign up for paid services. Egress already transcodes once and can emit many RTMP URLs from that one encode, which is the self-host path. Hosted Casthop could still put a single RTMP into Stream later if the delivery math wins. See [`MEASUREMENTS.md`](https://github.com/casthop/casthop/blob/main/MEASUREMENTS.md) in the repo.

## Control plane

The app is a Hono Worker with one Durable Object per studio (stage, layout, chat, destinations) and D1 for the studio index. R2 stores per-person ISO chunks uploaded from each browser during a show. The mixed MP4 still lands on the Egress volume. Hot Worker endpoints stay TypeScript; a workers-rs port was measured (`bun run bench:worker`) and did not win on CPU, cold start, or bundle size.

## Destination chat

While live, the studio Durable Object polls YouTube `liveChatMessages.list` if Worker secrets are set (`worker/chat-ingest.ts`). Comments join the in-room chat list. Hosts can pin one onto the Canvas2D overlay. The poll cursor (`liveChatId`, page token) is omitted from public studio state. X and LinkedIn are not ingested.

## Live badge

The studio pill is `live` only when Egress is producing output: stream bytes or duration, or a short settle after RTMP `started_at` (LiveKit can report a start before MediaMTX has the stream). Until then the pill stays on Starting. If the compositor Chrome dies, the heartbeat drops Live and the studio retries with backoff.
