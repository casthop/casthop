配信先は RTMP URL です。配信先ごとに **16:9**（番組）か **9:16**（縦の合成）を選べます。同じ比率の配信先は Egress の 1 回のエンコードを共有します。

## ローカルの代替

最初から、配信先は YouTube、LinkedIn、X 向けの MediaMTX 代替です:

| 配信先 | Ingest | 確認 |
|---|---|---|
| YouTube 代替 | `rtmp://127.0.0.1:1935/live/youtube` | `ffprobe rtmp://127.0.0.1:1935/live/youtube` |
| LinkedIn 代替 | `rtmp://127.0.0.1:1935/live/linkedin` | 同じ、`/live/linkedin` |
| X 代替 | `rtmp://127.0.0.1:1935/live/x` | 同じ、`/live/x` |

## 本番の配信先

本番では、各スタジオのオーナーが本物の YouTube、LinkedIn、X インジェスト URL を配信先パネルで入力します。`RTMP_*` の既定値が新しいスタジオにコピーされるのはループバックを指す場合だけなので、本物のストリームキーは入れないでください。Casthop は配信先を検証します。クライアントから受け付けるのは `rtmp:` URL だけで、プライベートネットワーク（RFC 1918）は拒否します。

## 状態、Live、復旧

各配信先行は、それぞれの RTMP 状態（`connecting`、`live`、`retrying`、`failed`）を出します。スタジオの Live 表示は、Egress が出力を出すまで「開始中」のままです。ストリームのバイト数か尺、あるいは RTMP の `started_at` のあとの短い settle です。コンポジタープロセスがあるだけでは Live になりません。

Egress やストリームが落ちると、スタジオは間隔を空けながら再試行します。署名付き LiveKit webhook に依存します。[セルフホスト](/docs/self-hosting) を見てください。

## 録画

| 場所 | 内容 |
|---|---|
| `data/recordings/` | 合成映像の Egress MP4。 |
| `data/rtmp/` | ローカル RTMP エッジからの MediaMTX fMP4。 |
| `RECORDINGS` (R2) | 個別録画がオンのときの人ごとの WebM。ホストは録画パネルからダウンロードします。 |

録画の中身は Rust ヘルパーで確認できます:

```bash
cargo run -p casthop-post -- inspect data/recordings/<file>.mp4
```

無音でないことを確かめるには `bash scripts/check-silent-audio.sh data/recordings/<file>.mp4` を実行します。

## チャット

スタジオにいる人は、部屋にコメントを送れます。番組がライブ中、Casthop は YouTube ライブチャット（`liveChatMessages.list`）もポーリングし、同じパネルに混ぜます。ホストと共同ホストは、コメント 1 件をコンポジターのオーバーレイ（Canvas2D のテロップ表示）にピンできます。ポーリングは API の `pollingIntervalMillis` に従います。資格情報が無いと YouTube の取り込みは隠れ、スタジオはエラーになりません。

必要な Worker secrets は、`YOUTUBE_API_KEY` に `YOUTUBE_LIVE_CHAT_ID` か `YOUTUBE_VIDEO_ID` を足すか、オーナーの進行中配信を探す OAuth リフレッシュ 3 点（`YOUTUBE_OAUTH_CLIENT_ID`、`YOUTUBE_OAUTH_CLIENT_SECRET`、`YOUTUBE_OAUTH_REFRESH_TOKEN`）です。[設定](/docs/configuration) を見てください。

X の API は有料プランが要ります。LinkedIn のライブコメントはパートナー API が要ります。どちらもつながっていません。配信先チャットの VOD / リプレイはなく、ポーリングはスタジオがライブのときだけ動きます。YouTube の page-token カーソルは Durable Object のストレージに留まり、ゲストや公開 GET / WebSocket 状態には送られません。

## 誰が何を見るか

- **オーナーと共同ホスト** は、サインイン中（セッション cookie）に配信先の完全な URL を受け取ります。
- **ゲストと公開リクエスト** が得るのは、マスクした末尾と `hasKey` フラグだけです。`GET /api/studios/:id` と WebSocket の `state` フレームに適用されます。
- ストリームキーは Durable Object のストレージにあり、リポジトリにはありません。
