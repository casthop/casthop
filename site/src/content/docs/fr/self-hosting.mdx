Casthop se compose de deux parties :

- **Les serveurs média :** LiveKit (fait circuler l’audio et la vidéo entre les navigateurs), Egress (mixe, enregistre et diffuse), Redis (leur permet de communiquer) et un serveur RTMP. Ils tournent dans Docker sur une machine que vous contrôlez.
- **Le serveur de l’application :** un Cloudflare Worker avec des Durable Objects (un par studio) et D1 (une petite base de données). Il sert l’interface du studio et l’API.

Faites d’abord fonctionner le [démarrage rapide local](/docs/getting-started). L’auto-hébergement est la même installation, avec de vraies clés et des adresses publiques.

## 1. Lancer les serveurs média

Partez de [`docker-compose.yml`](https://github.com/casthop/casthop/blob/main/docker-compose.yml) et des fichiers de config dans [`infra/`](https://github.com/casthop/casthop/tree/main/infra). En local, ils se lient à `127.0.0.1`. Sur un serveur, LiveKit doit être joignable par vos invités, en général en `wss://` derrière TLS. Le serveur RTMP peut être MediaMTX, nginx-rtmp, ou rien du tout si vous ne diffusez que vers YouTube et d’autres vraies plateformes.

## 2. Créer de vraies clés d’API

Le dépôt fournit des clés de test publiques (`devkey`). Créez les vôtres :

```bash
lk generate-keys
```

Mettez la clé et le secret dans `infra/livekit.yaml` (`keys:` et `webhook.api_key`) et dans `infra/egress.yaml`. L’application renvoie 503 si les clés de test sont utilisées avec un LiveKit qui n’est pas sur `127.0.0.1`. C’est voulu.

## 3. Créer les ressources Cloudflare

```bash
bunx wrangler d1 create casthop
bunx wrangler r2 bucket create casthop-recordings
```

Copiez le `database_id` D1 qu’il affiche dans `wrangler.jsonc`. Les tables sont créées à la première requête, il n’y a donc pas d’étape de migration.

## 4. Définir les variables et les secrets

Dans `wrangler.jsonc`, sous `vars`, définissez au moins `LIVEKIT_API_KEY`, `LIVEKIT_HTTP_URL`, `PUBLIC_LIVEKIT_URL`, `EGRESS_TEMPLATE_URL` et `PUBLIC_ORIGIN`. Ajoutez ensuite les secrets :

```bash
bunx wrangler secret put LIVEKIT_API_SECRET
bunx wrangler secret put HOST_KEY_SECRET
```

Utilisez une valeur aléatoire distincte pour `HOST_KEY_SECRET`. Sans elle, les clés d’hôte utilisent le secret LiveKit : changer les clés LiveKit plus tard vous verrouillerait hors des studios existants.

Définissez `MAIL_WEBHOOK_URL` pour que les e-mails de connexion partent vers un vrai service d’envoi. Tous les réglages sont dans [Configuration](/docs/configuration).

## 5. Compiler et déployer

```bash
bun install
bun run build
bunx wrangler deploy
```

Ouvrez `https://<your site>/api/health`. Vous devez voir `"ok":true`.

## 6. Pointer LiveKit vers l’application

Réglez `webhook.urls` de LiveKit sur :

```
https://<your site>/api/livekit/webhook
```

Les webhooks sont signés avec votre clé LiveKit. C’est ainsi que le studio apprend qu’Egress a planté ou qu’un stream est tombé, pour pouvoir réessayer. Egress doit aussi pouvoir ouvrir `EGRESS_TEMPLATE_URL`.

## 7. Proxies

Si l’application est derrière votre propre reverse proxy, définissez `CASTHOP_TRUST_FORWARDED=1` pour que la connexion et les limites d’invités voient la vraie adresse du client. Sur Cloudflare, ce n’est pas nécessaire.

## Destinations, replays et clips

- Les propriétaires de studio saisissent de vraies adresses YouTube, LinkedIn, X ou d’autres adresses RTMP studio par studio. Voir [Destinations](/docs/destinations).
- Le MP4 mixé va dans le dossier de sortie d’Egress. Transformez-le en replay avec `casthop-post hls`, puis `POST /api/studios/:id/replays` avec `visibility` réglé sur `private` ou `public`. Les replays privés sont pour le propriétaire et les co-hôtes. Les replays publics se lisent sur `/watch/:id`.
- En direct, **Clip** (ou la touche C) sauvegarde les 30 ou 60 dernières secondes. Les clips suivent les mêmes règles privé et public.

## Limites intégrées

- Connexion : toutes les 15 minutes, 5 demandes de lien par réseau et 3 liens par e-mail.
- Invités : chaque réseau (une adresse IPv4 ou un bloc IPv6 /64) peut ajouter jusqu’à 10 nouveaux invités par minute et occuper 16 places d’invité dans un studio. Les invités partis depuis plus d’une minute libèrent leur place quand le studio est plein.

## Pas encore inclus

- **TURN.** Les invités derrière des pare-feu stricts peuvent ne pas se connecter. Faites tourner votre propre serveur TURN avec LiveKit si vous en avez besoin.
- **Chat X et LinkedIn.** Le chat YouTube, Twitch et Kick fonctionne. X n’a pas d’API de chat gratuite, et LinkedIn demande une API partenaire.

Mesurez votre propre installation avant de vous y fier. Les chiffres enregistrés sont dans [`MEASUREMENTS.md`](https://github.com/casthop/casthop/blob/main/MEASUREMENTS.md).
