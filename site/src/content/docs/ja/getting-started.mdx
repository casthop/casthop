Casthop は、ブラウザで動くオープンソースのライブスタジオです。ホストとしてサインインし、ゲストにリンクを送り、最大 6 人をステージに上げ、ミックスした 1 本の映像を複数の配信サイトへ同時に送れます。録画も残ります。

このページでは、Linux マシン 1 台で、約 10 分で動かすところまで進めます。有料アカウントは要りません。ここでの「配信サイト」はローカルのテスト用サーバーなので、YouTube に触れずにライブ配信を試せます。

## 必要なもの

- **Linux**、Docker、Docker Compose。macOS と Windows は追加の手順が必要です。[Docker Desktop](#docker-desktop-macos-と-windows) を見てください。
- **[Bun](https://bun.com) 1.4.5 以上。** Bun は、このリポジトリが使う JavaScript ランタイム兼パッケージマネージャーです。npm は使わないでください。
- スタジオを開くための **Chrome か、ほかの Chromium 系ブラウザ**。

Rust は要りません。コンパイル済みの WebAssembly ファイルはリポジトリに入っています。

## クイックスタート

各手順は、[Casthop リポジトリ](https://github.com/casthop/casthop) のルートで実行します。

**1. コードを取得します。**

```bash
git clone https://github.com/casthop/casthop.git
cd casthop
```

**2. 設定のサンプルをコピーします。**

```bash
cp .env.example .env
cp .dev.vars.example .dev.vars
```

`.env` は Docker が読みます。`.dev.vars` はアプリサーバーが読みます。どちらも git の管理対象外で、初期値のまま動きます。

**3. 録画用のフォルダーを作ります。**

```bash
mkdir -p data/recordings data/rtmp && chmod 777 data/recordings
```

録画の処理は Docker の中で別のユーザーとして動くため、`data/recordings` への書き込み権限が必要です。

**4. メディアサーバーを起動します。**

```bash
docker compose up -d
docker compose ps
```

`redis`、`livekit`、`egress`、`mediamtx` の 4 つのサービスが動いていれば成功です。LiveKit はブラウザ間で音声と映像をやり取りします。Egress はステージを 1 本の映像にミックスして送り出します。MediaMTX は YouTube、LinkedIn、X の代わりを務めます。Redis は LiveKit と Egress をつなぎます。

初回はイメージをダウンロードするため、数分かかることがあります。

**5. アプリをインストールして起動します。**

```bash
bun install
bun run dev
```

`Local: http://127.0.0.1:5173/` と表示されます。このターミナルは開いたままにしてください。アプリは `127.0.0.1` だけで待ち受けるので、ネットワーク上のほかのマシンからは届きません。

**6. 正常に動いているか確認します。**

2 つ目のターミナルで実行します。

```bash
curl http://127.0.0.1:5173/api/health
```

`{"ok":true,"livekit":{"ok":true},"maxOnStage":6}` と表示されます。`ok` が `false` なら、アプリが LiveKit に届いていません。[トラブルシューティング](#トラブルシューティング) を見てください。

## 最初の配信

1. [http://127.0.0.1:5173](http://127.0.0.1:5173) を開き、メールアドレスを入力します。
2. ローカルではメールは送られません。サインインリンクは、`bun run dev` を動かしているターミナルの `[casthop mail]` の下に表示されます。リンクを開いて **Sign in** をクリックします。
3. スタジオにタイトルを付けて、**Open studio** をクリックします。
4. ゲストリンクをコピーして、別のブラウザウィンドウで開くか、誰かに送ります。ゲストにアカウントは要りません。[ゲスト](/docs/guests) を見てください。
5. ゲストをステージに上げます。ステージには最大 6 人まで上がれます。
6. **Go live** を押し、配信先を選んで確定します。ステータス表示は最初 **Starting** で、映像が実際に流れ始めると **Live** に変わります。配信先ごとに、それぞれの状態も表示されます。

送り出した映像を確認するには、`ffprobe rtmp://127.0.0.1:1935/live/youtube` を実行します。録画は `data/recordings/` に書き込まれます。[配信先](/docs/destinations) を見てください。

## 任意の追加機能

どれも、`.dev.vars` に設定して `bun run dev` を再起動するまでは無効です。それぞれの説明は [設定](/docs/configuration) にあります。

- **GitHub でサインイン:** `GITHUB_CLIENT_ID` と `GITHUB_CLIENT_SECRET`。
- **スタジオに YouTube のチャットを表示:** `YOUTUBE_API_KEY` と、`YOUTUBE_LIVE_CHAT_ID` または `YOUTUBE_VIDEO_ID`。
- **Twitch と Kick のチャット:** `TWITCH_CHANNEL` と `KICK_CHATROOM_ID`。
- **サインインリンクをターミナルではなくブラウザに返す**（テストと `bun run measure` 用）: `CASTHOP_DEV_LOGIN=1`。

## トラブルシューティング

**`permission denied while trying to connect to the Docker daemon socket`**
ユーザーが `docker` グループに入っていません。`sudo usermod -aG docker $USER` を実行して、ログアウトしてからログインし直すか、Docker のコマンドの前に `sudo` を付けてください。

**`Port 5173 is already in use`**
ほかの開発サーバーが動いています。止めるか、`ss -ltnp | grep 5173` で探してください。録画の処理が `5173` を前提にしているため、Casthop はほかのポートを選びません。

**ヘルスチェックが `"ok":false` になる**
LiveKit が動いていないか、届きません。`docker compose ps` と `docker compose logs livekit` を確認してください。ポート `7880` が空いている必要があります。

**`Refusing default LiveKit devkey/secret outside local loopback`**
公開されているテスト用キーのまま、`127.0.0.1` 以外の LiveKit サーバーを指しています。本物のキーを作り（[セルフホスト](/docs/self-hosting) を見てください）、`.dev.vars` に入れてください。

**サインインリンクが届かない**
受信箱ではなく、`bun run dev` のターミナルを見てください。リンクを何度も請求した場合は、サインインが数分間止まります（15 分ごとに、1 つのネットワークから 5 回、1 つのメールに 3 通まで）。

**Starting のまま進まない**
Egress がスタジオのページを開けないか、MediaMTX に届いていません。`docker compose logs egress` を確認してください。`bun run dev` が動き続けていることと、`data/recordings` に書き込めることも確かめてください。

**マシンにカメラがない**
Casthop はテスト用の映像と無音の音声に切り替わるので、サーバーや VM でも参加できます。Chrome を `--use-fake-device-for-media-stream` 付きで起動する方法もあります。

**Bun がバージョンの警告を出す**
`bun upgrade` を実行してください。このリポジトリは Bun 1.4.5 以上を前提にしています。

## Docker Desktop (macOS と Windows)

compose ファイルは host networking を使いますが、これは Linux でしか動きません。Docker Desktop では次のようにします。

- 各サービスから `network_mode: host` を削除します。
- `127.0.0.1:7880-7882`、`127.0.0.1:1935`、`127.0.0.1:8888`、`127.0.0.1:6379`、`127.0.0.1:9090` を公開します。
- LiveKit の `rtc.node_ip` を `host.docker.internal` にします。
- Egress の `ws_url` と Redis を `host.docker.internal` に向けます。

この方法でも、同じマシン上のブラウザの映像が不安定になることがあります。いまサポートしているのは Linux です。
