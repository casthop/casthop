Casthop tiene dos mitades que hablan por la API Twirp de LiveKit.

- **Plano de medios:** LiveKit, Egress, Redis y un borde RTMP.
- **Plano de control:** un Cloudflare Worker con Durable Objects y D1.

El [`docker-compose.yml`](https://github.com/casthop/casthop/blob/main/docker-compose.yml) del repo es el plano de medios para uso local. Los archivos de configuración viven en [`infra/`](https://github.com/casthop/casthop/tree/main/infra).

## 1. Plano de medios

Levanta LiveKit, Egress y Redis, más un borde RTMP. El borde puede ser MediaMTX (lo que usa el compose), nginx-rtmp, o un destino real como YouTube.

## 2. Claves de API de verdad

El repo trae el par `devkey` publicado solo para uso local. Genera claves reales:

```bash
lk generate-keys
```

Sustituye los valores locales en `infra/livekit.yaml` y `infra/egress.yaml`.

El Worker responde 503 si el `devkey` publicado se usa con una URL de LiveKit que no sea loopback. Es a propósito.

## 3. Webhooks

Apunta `webhook.urls` de LiveKit a:

```
https://<worker>/api/livekit/webhook
```

Los webhooks van firmados. Así es como un crash de Egress y una caída de RTMP llegan al estudio para reintentar. La pastilla Live espera salida real (bytes/duración o un settle corto de RTMP) antes de mostrar Live.

## 4. Desplegar el Worker

```bash
wrangler deploy
```

Pon los secretos en Worker secrets, nunca en git:

```bash
wrangler secret put LIVEKIT_API_SECRET
wrangler secret put HOST_KEY_SECRET
```

Define un `HOST_KEY_SECRET` dedicado. Sin él, las host keys caen al secreto de LiveKit; rotar las claves de LiveKit bloquearía los estudios ya existentes.

## 5. Origen público y proxies

- Define `PUBLIC_ORIGIN` con la URL pública del sitio. Se usa en el correo del magic link, las invitaciones de coanfitrión y el callback de GitHub. Si queda vacío, se usa el Host de loopback; en producción, defínelo para que un Host falsificado no genere enlaces hacia un atacante.
- Detrás de un reverse proxy, pon `CASTHOP_TRUST_FORWARDED=1` para que los límites de inicio de sesión por IP usen la dirección real del cliente. Sin eso, todos comparten un bucket `local`. Cloudflare pone `request.cf`, así que no lo necesitas ahí. No lo actives en `wrangler dev`.

## 6. Inicio de sesión

El inicio de sesión es un magic link por correo. Por defecto el enlace se registra en la consola del Worker. Define `MAIL_WEBHOOK_URL` para hacer POST de JSON `{ to, subject, text }` a tu propio mailer. GitHub OAuth es opcional. Mira [Configuración](/docs/configuration).

## 7. Destinos y grabaciones

Apunta las URLs de destino al ingest real de YouTube, LinkedIn y X. Mira [Destinos](/docs/destinations). Si quieres, ejecuta `casthop-post normalize` y copia los MP4 terminados a R2 para el replay. R2 está bound como encaje para eso. Por ahora las grabaciones se quedan en el volumen de Egress.

## Lo que este árbol no cubre

TURN para invitados detrás de NAT estricto y un visor de replay en R2 no están. El ingest de chat en vivo de YouTube es opcional (Worker secrets); los comentarios de X y LinkedIn no están cableados. El desenfoque de cámara, el compose Canvas2D fuera del hilo, Live-cuando-produce y el retry de crash de Egress sí. Mide tu propio setup antes de fiarte. Variables de entorno: [Configuración](/docs/configuration).
