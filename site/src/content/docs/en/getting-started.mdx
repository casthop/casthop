Casthop is an open-source live studio that runs in the browser. You sign in as the host, send guests a link, put up to six people on stage, and send one mixed video to several streaming sites at once. A recording is kept.

This page gets it running on one Linux machine in about ten minutes. Nothing here needs a paid account. The "streaming sites" are local test servers, so you can go live without touching YouTube.

## What you need

- **Linux** with Docker and Docker Compose. macOS and Windows need extra steps, see [Docker Desktop](#docker-desktop-macos-and-windows).
- **[Bun](https://bun.com) 1.4.5 or newer.** Bun is the JavaScript runtime and package manager this repo uses. Do not use npm.
- **Chrome or another Chromium browser** to open the studio.

You do not need Rust. The compiled WebAssembly file is in the repo.

## Quick start

Run each step from the root of the [Casthop repository](https://github.com/casthop/casthop).

**1. Get the code.**

```bash
git clone https://github.com/casthop/casthop.git
cd casthop
```

**2. Copy the example settings.**

```bash
cp .env.example .env
cp .dev.vars.example .dev.vars
```

`.env` is read by Docker. `.dev.vars` is read by the app server. Both are ignored by git, and the defaults work as is.

**3. Make the folders for recordings.**

```bash
mkdir -p data/recordings data/rtmp && chmod 777 data/recordings
```

The recorder runs as another user inside Docker, so it needs write access to `data/recordings`.

**4. Start the media servers.**

```bash
docker compose up -d
docker compose ps
```

You should see four services running: `redis`, `livekit`, `egress` and `mediamtx`. LiveKit moves the audio and video between browsers. Egress mixes the stage into one video and sends it out. MediaMTX stands in for YouTube, LinkedIn and X. Redis lets LiveKit and Egress talk.

The first run downloads the images, which can take a few minutes.

**5. Install and start the app.**

```bash
bun install
bun run dev
```

You should see `Local: http://127.0.0.1:5173/`. Leave this terminal open. The app only listens on `127.0.0.1`, so other machines on your network cannot reach it.

**6. Check that it is healthy.**

In a second terminal:

```bash
curl http://127.0.0.1:5173/api/health
```

You should see `{"ok":true,"livekit":{"ok":true},"maxOnStage":6}`. If `ok` is `false`, the app cannot reach LiveKit. See [Troubleshooting](#troubleshooting).

## Your first stream

1. Open [http://127.0.0.1:5173](http://127.0.0.1:5173) and enter your email.
2. No email is sent locally. The sign-in link is printed in the terminal running `bun run dev`, under `[casthop mail]`. Open it and click **Sign in**.
3. Give the studio a title and click **Open studio**.
4. Copy the guest link and open it in another browser window, or send it to someone. Guests need no account. See [Guests](/docs/guests).
5. Bring the guest on stage. Up to six people can be on stage.
6. Press **Go live**, pick destinations, and confirm. The pill shows **Starting** and turns **Live** once video is really flowing. Each destination shows its own status.

To watch what went out, run `ffprobe rtmp://127.0.0.1:1935/live/youtube`. The recording is written to `data/recordings/`. See [Destinations](/docs/destinations).

## Optional extras

All of these are off until you set them in `.dev.vars`, then restart `bun run dev`. Each one is explained in [Configuration](/docs/configuration).

- **GitHub sign-in:** `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET`.
- **YouTube chat in the studio:** `YOUTUBE_API_KEY` plus `YOUTUBE_LIVE_CHAT_ID` or `YOUTUBE_VIDEO_ID`. Set `YOUTUBE_CHAT_STUDIO_ID` to the studio that should show it.
- **Twitch and Kick chat:** `TWITCH_CHANNEL` and `KICK_CHATROOM_ID`.
- **Sign-in link in the browser instead of the terminal**, for tests and `bun run measure`: `CASTHOP_DEV_LOGIN=1`.

## Troubleshooting

**`permission denied while trying to connect to the Docker daemon socket`**
Your user is not in the `docker` group. Run `sudo usermod -aG docker $USER`, log out and back in, or prefix the Docker commands with `sudo`.

**`Port 5173 is already in use`**
Another dev server is running. Stop it, or find it with `ss -ltnp | grep 5173`. Casthop does not pick another port, because the recorder expects `5173`.

**Health shows `"ok":false`**
LiveKit is not running or not reachable. Check `docker compose ps` and `docker compose logs livekit`. Port `7880` must be free.

**`Refusing default LiveKit devkey/secret outside local loopback`**
You pointed the app at a LiveKit server that is not on `127.0.0.1` while still using the public test keys. Generate real keys (see [Self-hosting](/docs/self-hosting)) and put them in `.dev.vars`.

**No sign-in link**
Look in the `bun run dev` terminal, not your inbox. If you asked for links many times, sign-in is paused for a few minutes (every 15 minutes: 5 requests per network, 3 links per email).

**Stuck on Starting**
Egress could not open the studio page or reach MediaMTX. Check `docker compose logs egress`. Make sure `bun run dev` is still running and `data/recordings` is writable.

**No camera on the machine**
Casthop falls back to a test picture and silent audio, so a server or VM can still join. You can also start Chrome with `--use-fake-device-for-media-stream`.

**Bun warns about the version**
Run `bun upgrade`. The repo expects Bun 1.4.5 or newer.

## Docker Desktop (macOS and Windows)

The compose file uses host networking, which only works on Linux. On Docker Desktop:

- remove `network_mode: host` from each service,
- publish `127.0.0.1:7880-7882`, `127.0.0.1:1935`, `127.0.0.1:8888`, `127.0.0.1:6379` and `127.0.0.1:9090`,
- set LiveKit `rtc.node_ip` to `host.docker.internal`,
- point Egress `ws_url` and Redis at `host.docker.internal`.

Browser video on the same machine can still be unreliable this way. Linux is the supported path for now.
