Casthop besteht aus zwei Teilen:

- **Medienserver:** LiveKit (bewegt Audio und Video zwischen Browsern), Egress (mischt, nimmt auf und streamt raus), Redis (lässt sie miteinander sprechen) und ein RTMP-Server. Sie laufen in Docker auf einem Rechner, den du kontrollierst.
- **App-Server:** ein Cloudflare Worker mit Durable Objects (eins pro Studio) und D1 (einer kleinen Datenbank). Er liefert die Studio-UI und die API aus.

Bring zuerst den [lokalen Schnellstart](/docs/getting-started) zum Laufen. Self-Hosting ist dasselbe Setup mit echten Schlüsseln und öffentlichen Adressen.

## 1. Medienserver starten

Fang mit der [`docker-compose.yml`](https://github.com/casthop/casthop/blob/main/docker-compose.yml) und den Config-Dateien in [`infra/`](https://github.com/casthop/casthop/tree/main/infra) an. Lokal binden sie an `127.0.0.1`. Auf einem Server muss LiveKit für deine Gäste erreichbar sein, meistens als `wss://` hinter TLS. Der RTMP-Server kann MediaMTX oder nginx-rtmp sein, oder gar nichts, wenn du nur zu YouTube und anderen echten Seiten streamst.

## 2. Echte API-Schlüssel erzeugen

Das Repo bringt öffentliche Testschlüssel (`devkey`) mit. Erzeuge deine eigenen:

```bash
lk generate-keys
```

Trag Schlüssel und Secret in `infra/livekit.yaml` (`keys:` und `webhook.api_key`) und `infra/egress.yaml` ein. Die App antwortet mit 503, wenn die Testschlüssel mit einem LiveKit genutzt werden, das nicht auf `127.0.0.1` läuft. Das ist Absicht.

## 3. Cloudflare-Ressourcen anlegen

```bash
bunx wrangler d1 create casthop
bunx wrangler r2 bucket create casthop-recordings
```

Kopiere die ausgegebene D1-`database_id` in `wrangler.jsonc`. Die Tabellen werden bei der ersten Anfrage angelegt, einen Migrationsschritt gibt es also nicht.

## 4. Variablen und Secrets setzen

Setz in `wrangler.jsonc` unter `vars` mindestens `LIVEKIT_API_KEY`, `LIVEKIT_HTTP_URL`, `PUBLIC_LIVEKIT_URL`, `EGRESS_TEMPLATE_URL` und `PUBLIC_ORIGIN`. Füge dann die Secrets hinzu:

```bash
bunx wrangler secret put LIVEKIT_API_SECRET
bunx wrangler secret put HOST_KEY_SECRET
```

Nimm für `HOST_KEY_SECRET` einen eigenen Zufallswert. Ohne ihn nutzen Host-Keys das LiveKit-Secret, ein späterer Wechsel der LiveKit-Schlüssel würde dich also aus bestehenden Studios aussperren.

Setz `MAIL_WEBHOOK_URL`, damit Anmelde-E-Mails an einen echten Mailer gehen. Alle Einstellungen stehen in [Konfiguration](/docs/configuration).

## 5. Bauen und deployen

```bash
bun install
bun run build
bunx wrangler deploy
```

Öffne `https://<deine Seite>/api/health`. Du solltest `"ok":true` sehen.

## 6. LiveKit auf die App zeigen lassen

Setz LiveKits `webhook.urls` auf:

```
https://<deine Seite>/api/livekit/webhook
```

Die Webhooks sind mit deinem LiveKit-Schlüssel signiert. So erfährt das Studio, dass Egress abgestürzt ist oder ein Stream weggebrochen ist, und kann es erneut versuchen. Egress muss außerdem `EGRESS_TEMPLATE_URL` öffnen können.

## 7. Proxys

Sitzt die App hinter deinem eigenen Reverse-Proxy, setz `CASTHOP_TRUST_FORWARDED=1`, damit Anmeldung und Gäste-Limits die echte Client-Adresse sehen. Auf Cloudflare brauchst du das nicht.

## Ziele, Replays und Clips

- Studio-Eigentümer tragen echte YouTube-, LinkedIn-, X- oder andere RTMP-Adressen pro Studio ein. Siehe [Ziele](/docs/destinations).
- Das gemischte MP4 landet im Egress-Ausgabeordner. Mach mit `casthop-post hls` ein Replay daraus und sende dann `POST /api/studios/:id/replays` mit `visibility` auf `private` oder `public`. Private Replays sind für den Eigentümer und Co-Hosts. Öffentliche laufen unter `/watch/:id`.
- Solange du live bist, speichert **Clip** (oder die Taste C) die letzten 30 oder 60 Sekunden. Clips folgen denselben Regeln für privat und öffentlich.

## Eingebaute Limits

- Anmeldung: alle 15 Minuten 5 Link-Anfragen pro Netzwerk und 3 Links pro E-Mail.
- Gäste: Jedes Netz (eine IPv4-Adresse oder ein IPv6-/64-Block) kann bis zu 10 neue Gäste pro Minute hinzufügen und 16 Gästeplätze in einem Studio belegen. Gäste, die vor mehr als einer Minute gegangen sind, geben ihren Platz frei, wenn das Studio voll ist.

## Noch nicht dabei

- **TURN.** Gäste hinter strengen Firewalls können sich eventuell nicht verbinden. Betreib bei Bedarf mit LiveKit einen eigenen TURN-Server.
- **X- und LinkedIn-Chat.** YouTube-, Twitch- und Kick-Chat funktionieren. X hat keine kostenlose Chat-API, und LinkedIn braucht eine Partner-API.

Miss dein eigenes Setup, bevor du dich darauf verlässt. Aufgezeichnete Zahlen stehen in [`MEASUREMENTS.md`](https://github.com/casthop/casthop/blob/main/MEASUREMENTS.md).
